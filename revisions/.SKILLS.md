# Reviewing a habit

## Recognize a problem that can be tested

During a review, read discrepant outcomes and follow their sources. For example, find episodes where a belief became stronger after a second percept and both percepts cite the same capture. Count distinct episodes and capture ancestry. Two backlinks to one encounter cannot establish recurrence. Write a proposal if the examples identify a shared rule and suggest an observable test. An operator can also initiate a proposal from one consequential example, giving the reason.

## Compare two readings of the same evidence

1. Pin the baseline and candidate versions, their configuration, and a fixed set of input record IDs. Define the expected result before comparing outputs. Include a case that should stay unchanged.
2. For the repeated-view example, test one episode with two percepts grounded in a single capture and another with independent views that reveal a handle. The candidate should prevent the first promotion and still allow the second when both views support the claim. Check the actual evidence cited by each result.
3. Run both readings in an isolated copy. Record the per-case outcomes and regressions, including any missing payloads. Mark a comparison inconclusive when necessary evidence is unavailable. Keep the live memories addressable under their original IDs.
4. Append a trial note linked to the proposal and its inputs. A reviewer can request a larger trial, reject the proposal, or accept a version for deployment. Record the reason, deployment reference, and a practical rollback condition.

## Carry a change forward

A change that merely improves a rule increments the producer version. A change to the meaning or shape of a stored field also assigns a new schema version. Specify how to read old records, how to detect the version, and what information an older record cannot supply. Test reading an old note before rollout. If existing memories need new interpretations, append derived records with provenance. When reversing a change, deploy the previous compatible version and append a rollback decision citing the observed failure.
