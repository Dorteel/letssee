# Interpreting a capture

| Operation | Inputs and resulting judgment |
| --- | --- |
| `locate_evidence(capture)` | Verify and decode the attachment through the capture reader. For images, use integer pixel coordinates in the original image and a half-open rectangle `[x0, y0, x1, y1)` measured from the upper left. Undo any crop or resize used by a detector. For joint states, use the joint name, array name, value and unit. |
| `describe_observation(evidence, method)` | Express one time-bounded, observable feature. Distinguish the visible blue curved rim from the candidate object that could explain it. Record the frame and clock bounds inherited from the capture. Joint readings retain the joint and its unit even if the header has no spatial frame. |
| `assess_interpretations(feature, quality)` | Compare candidates against the cited evidence. For each plausible reading, name a cue that supports it or would discriminate it from the others. Mark incomplete support as `tentative`. Mark the narrow claim `supported` when the cited feature is clear. If an inspection succeeded but visibility precluded a claim, use `indeterminate` and describe the obstruction. |
| `write_percept(result, source, revision)` | Check recording scope for the proposed text, attach the capture link and method revision, and commit. Reuse the vault's derivation ID scheme with source ID, method revision and a stable claim key. A new method revision creates a fresh interpretation. Include `supersedes` only when the new reading explicitly corrects an earlier claim. |

On a missing or corrupt attachment, report a read failure and preserve the capture link for diagnosis. An empty detection list alone gives no grounds for claiming the scene was empty. During recall, inspect the original locator, the named alternatives and any superseding note before treating a percept as evidence for a broader claim.
