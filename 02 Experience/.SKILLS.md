# Recall an experience

1. Capture the cue in the robot's own terms, such as “The drawer scraped again. What helped last time?” Link a current percept or question if one prompted the search.
2. Look for episodes using the distinctive sound, the object and the action. Record the cues actually tried. Inspect the linked percepts when the answer depends on a fine detail such as which movement came first.
3. For each plausible match, name the detail it shares with the cue and a detail that weakens the match. Keep separate episodes distinct even when their settings are similar.
4. Write one `recall` note. Put the cue note and the records used in `sources`, then identify their roles in the body. State the answer the records support and label any new inference. With no match, record the search scope and leave the answer open.
5. If the recollection changes a plan, link the new plan back to the recall. If further evidence changes the recollection, write a fresh recall linked to the earlier one and the new evidence so the original decision remains intelligible.

## Implementation interface

```text
class Recall(cue, time_of_recall, search_scope, matches, answer, open_questions, sources)
recall_experience(cue: Cue, scope: List<Episode>) -> Recall
```
