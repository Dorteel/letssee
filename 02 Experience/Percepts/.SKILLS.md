# Interpret a sensory window

1. Choose the smallest capture window that contains the change. Read the source clock, units and recorded gaps. Cite the exact offsets used. If the streams cannot be aligned within the timing precision the interpretation needs, describe the timing as unresolved.
2. Extract the features a reader can check, such as a current increase on one joint or an audio peak. Record the method when it affects the result, including a threshold, filter or model version if used.
3. Propose a reading and look for a competing cause. Name which features support it, which conflict and what additional measurement could distinguish the two. Use a plain confidence judgment with a reason.
4. Save the `percept` with its sensory sources. If later inspection changes the reading, create a percept that cites the previous percept and the decisive source. Identify the changed interpretation in its body. Episodes can then cite the revision explicitly.

## Implementation interface

```text
class Percept(window, features, method, interpretation, confidence_reason, alternatives, sources)
interpret_window(window: TimeRange, streams: List<SourceRange>, method: Method) -> Percept
```
