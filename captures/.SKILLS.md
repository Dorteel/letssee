# Recording and inspecting a sample

1. `select_sample(message, receipt, policy)` checks the source topic and the recording permission for the current setting before staging anything. Apply the configured sampling period on the receiver's steady clock. A permitted metadata-only record has `availability: withheld`, an empty asset list and a short reason that the policy permits storing. If metadata is also restricted, discard the sample.
2. `describe_sample(message, receipt)` copies the source type and frame, including an empty or unknown frame. Copy the acquisition stamp with its clock domain and epoch. A point observation has equal start and end. If the acquisition stamp's meaning is unknown, leave both bounds null. Keep the UTC receipt time in its own field. Assign an ID and retain the draft and ID together across retries.
3. `preserve_sample(message, draft)` serializes the complete message in CDR, stages it through the writer's local staging adapter and computes SHA-256 over the exact staged bytes. Save the byte length, ROS message type and type-definition version alongside the digest. Submit the manifest and its staging token to the vault writer. An uncertain reply calls for a retry with the same record, asset contents and ID.
4. `mark_gap(stream, interval, cause)` creates one metadata-only record per continuous outage after stream monitoring starts. Measure a receive-side silence or queue overflow using the recorder's steady clock and boot epoch. Close the interval on recovery or orderly shutdown. State whether the cause was observed locally or is unknown. Use a lost-sample count only when the driver or queue provides it.
5. `read_sample(capture)` resolves the sibling named in the manifest, checks the length and digest, and decodes using the declared type version and serialization. Within the capture's permitted audience, the local reader uses this operation to display the full image and outline the pixel rectangle cited by a percept. An unavailable attachment, unsupported decoder or checksum mismatch yields an explicit read failure. A reader can still inspect the timing and quality metadata.
6. `correct_capture(prior, correction)` writes a new ID and cites the prior note in both `sources` and `supersedes`. Describe the changed field and the evidence for the change. To carry the same payload forward, verify its length and digest and check recording permission again. Stage the original bytes under the new ID's sibling filename and retain their original digest. If the original bytes are missing or corrupt, use `availability: unavailable`, an empty asset list and the observed reason. If recording permission permits only metadata, use `withheld`. The correction describes the same acquisition, so readers following its ancestry count a single sample.
