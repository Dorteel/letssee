# Camera look and observation

`/agency/executor` is the sole live writer of attempt events and the action client for the stationary camera head. Commit notifications on `/vault/committed` (`mind_interfaces/msg/RecordCommitted`) prompt a read of the committed note. The executor uses these reads to reassess attempts and detect withdrawn intentions. Vault events and reconciliation can only update knowledge or request cancellation of an active goal.

### Live admission

An operator client calls `/agency/try_look` (`mind_interfaces/srv/TryLook`). The request contains `string intention_id`. The response contains `bool accepted`, `string attempt_id` and `string reason`. Acceptance means the executor admitted one attempt. A retry for a reserved intention returns the existing accepted attempt and its ID, including when its outcome is unknown. A refusal before reservation returns an empty ID and the reason. Configure one active executor for the body, with exclusive command access. Multiple requests to this service are serialized.

The executor uses `/vault/commit` (`mind_interfaces/srv/CommitRecord`) with `record_id`, `folder=attempts`, `markdown` and empty `staged_assets`. Check `ok`, `path` and `error` before exposing the reservation as admitted. After a confirmed new commit and a final freshness check, the live handler starts the action asynchronously. Pass the UUID portion of the reservation ID as the ROS goal UUID. Distinct phases use distinct note IDs. Keep the bytes and ID of a pending write stable across retries, and reconcile existing phase records before appending another one.

The caller may cancel its attempt through `/agency/cancel_look` (`mind_interfaces/srv/CancelLook`). Its request contains `string attempt_id`. Its response contains `bool received` and `string detail`. A positive response confirms receipt for that attempt. Serialize dispatch and cancellation decisions. A cancellation that arrives before dispatch consumes the reservation and records `skipped`. If a goal was sent but its acceptance reply is pending, remember the cancellation and forward it as soon as the goal handle arrives. If the response to dispatch is lost, follow the bounded recovery path below. Cancel an accepted goal through the standard ROS action cancellation interface. A repeated cancellation of a known attempt reports its current state. An unknown ID receives a negative response.

### Body action

`/body/camera_head` serves `/body/look` with the proposed `mind_interfaces/action/Look` type. The goal, result and feedback sections below use ROS interface-definition order. Each angle is absolute and expressed in radians relative to the calibrated fixed camera mount. Zero looks along its forward axis. Positive yaw points left and positive pitch points up.

```text
string attempt_id
float64 yaw_rad
float64 pitch_rad
builtin_interfaces/Time expires_at
builtin_interfaces/Duration timeout
---
float64 final_yaw_rad
float64 final_pitch_rad
builtin_interfaces/Time completed_at
bool completion_time_valid
float64 completion_error_s
string detail
---
float64 yaw_rad
float64 pitch_rad
```

The live body's `expires_at` uses Unix-epoch UTC. Reject a goal on expiry, unsynchronized time, duplicate ID, busy head, nonfinite targets, nonpositive timeout, absent calibration, inhibited drive or targets outside the platform's calibrated bounds. The head enforces its own limits throughout the move and measures its maximum run time on a monotonic clock. On cancellation it stops the head and returns the canceled result once the stop is confirmed. A local inhibit or elapsed deadline stops motion and produces an aborted result. Unavailable measurements use NaN on the wire and null in the vault. The executor records a denied goal as rejected and maps terminal action status to the body result on accepted goals. A cancel acknowledgement leaves the result pending until a terminal status arrives. [ROS 2 action design](https://design.ros2.org/articles/actions.html)

The head stamps `completed_at` at its terminal observation, such as the measurement that confirms the target angle has settled. Use the synchronized body clock in Unix-epoch UTC and supply a conservative absolute error bound in seconds as `completion_error_s`. Set `completion_time_valid` true only when the timestamp and finite, nonnegative bound are trustworthy. Otherwise send false, a zero time and NaN for the error. A cached action result retains these original values. The executor stores a valid completion in the return note's `event_at`, its error bound in `completion_error_s` and the UTC time of receiving the reply in `result_received_at`. When no valid completion exists, both body timing fields are null.

### Timing and recovery

The executor parameter `look_timeout_s` (double, default 3.0 seconds) caps a look. Set the requested timeout to the smaller of this value and the remaining intention lifetime. The body clamps it to its own platform limit. The executor requests action cancellation if the intention is withdrawn or its deadline passes while the goal is active. The body has a local inhibit available to the operator independent of vault or executor availability.

`observation_window_s` (double, default 5.0 seconds) bounds the search for a post-look observation. Use the capture manifest's `earliest_utc` and `latest_utc` and cite its `clock_alignment`. These bounds already include the alignment error. If a later calibration supplies the mapping, cite the corrected manifest containing it. Accept the observation only if its earliest time is after the latest plausible body completion and its latest time is within one observation window of the earliest plausible completion. The camera pose must still match. Overlapping intervals, missing clock bounds or a receipt timestamp alone leave the assessment inconclusive.

On startup and periodic reconciliation the executor reads reservations and later events. Exclude any request currently owned by a live handler from crash recovery. For an orphaned reservation missing a return, query the action server for a cached result by goal UUID, with a bounded wait through the original expiry plus `result_grace_s` (double, default 2.0 seconds). Missing or expired results become `unknown`. Recovery never sends a new look goal. A stopped or disconnected executor can still leave a moving head for the remainder of its body-enforced timeout. A fresh look then requires a newly considered intention, a live request and an available head. Replay runs without access to the live body's command endpoints.
