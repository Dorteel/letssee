# Attempt one look

### Admit a live request

`reserve(intention_id, now) -> reservation_or_reason`

Serialize admission in the single active executor. Check for an existing reservation first and return its ID on a duplicate request. For a new reservation, resolve the current intention and confirm open status, choice of look, finite angles, freshness, a unique current version and availability of the body. Derive the reservation UUID with UUIDv5 using the common namespace `58664475-41a0-4770-949f-fa9427ad0cea` and the UTF-8 name `attempt:camera-reservation:v1:<intention_id>`. Freeze this identity rule across executor upgrades. Use `attempt-<uuid>` for both its note ID and its attempt ID. This identifies the same reservation after a lost reply.

Commit that reservation before sending a goal. Carry the one-time permission to dispatch in the live request handler. Only the handler that admitted the new request may send one goal. Treat any conflicting commit as an existing or uncertain reservation and reconcile. A lost commit reply can leave a reservation on disk without a corresponding movement. Its existence consumes the request.

### Record the body return

`finish(reservation, body_reply, result_received_at) -> return_note`

Persist one return note linked to the reservation. Distinguish a rejected goal, a confirmed cancellation, a body abort, a reached angle and an unknown result. Record measured angles when available. If admission conditions changed before dispatch, write `skipped` with the reason. If a goal may already have crossed the boundary to the body, a timeout or lost reply yields `unknown`. On recovery query the body's cached result by the reserved UUID if available. A later authoritative result can supersede an earlier unknown return.

Read the terminal observation time and its clock error bound from the body result. Preserve the executor's receipt time separately, including for a cached result retrieved after restart. An invalid completion time leaves the return note's `event_at` and `completion_error_s` null even when the angle and terminal status are known.

### Compare with the world

`assess(intention, body_return, percepts) -> assessment`

Find a fresh capture or percept after the head settled. Verify the capture's acquisition interval falls in the [post-look window](.BLUEPRINT.md) after accounting for both clocks' errors. Confirm the same tray or another scene reference and apply the intention's written test. Record `met` if the feature is visible, `contradicted` if usable evidence rules it out, or `inconclusive` when the sightline, timing or detail leaves doubt. When the useful observation window closes without a suitable frame, record the gap and an inconclusive assessment. A later frame in the relevant time window can justify a new assessment that supersedes it. The planner decides what to do with that evidence.
