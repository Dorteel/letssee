# The ROS 2 graph and the vault

Run the cognitive nodes beside a single Obsidian vault on a filesystem that supports durable writes and atomic rename. The body can run on another machine. Sensor samples enter over ROS 2. A committed Markdown path is the handoff between cognitive processes. A running node can forget its work queue and recover by reading the vault. Obsidian and the recall service read the same records.

## Nodes and ownership

| Node | Reads or receives | Produces |
| --- | --- | --- |
| `/sense/recorder` | Camera images and joint state from drivers | [Captures](captures/.BLUEPRINT.md) and their original payloads |
| `/sense/interpreter` | Validated sample manifests and bytes | [Percepts](percepts/.BLUEPRINT.md) with evidence locators |
| `/memory/episode_builder` | Percepts, capture gaps, attempt events, and prior accounts | [Episodes](episodes/.BLUEPRINT.md) with event order and gaps |
| `/memory/belief_reviewer` | Situated evidence and prior claims | [Beliefs](beliefs/.BLUEPRINT.md) with scope, support, and counterevidence |
| `/agency/planner` | A question, current evidence, and past outcomes | [Intentions](intentions/.BLUEPRINT.md) with a test and a choice |
| `/agency/executor` | Live requests, current intentions, body returns, and fresh percepts | One bounded look per admitted intention version and linked [attempt events](attempts/.BLUEPRINT.md) |
| `/body/camera_head` | The executor's look goal, encoder feedback, local inhibit, and mount limits | A bounded camera movement, action feedback, and a terminal result |
| `/reflection/reviewer` | A requested rule review and cited examples | [Revision proposals](revisions/.BLUEPRINT.md) for offline comparison |
| `/vault/writer` | Candidate notes and staged capture bytes | Validated records on disk and commit notices |
| `/vault/librarian` | Committed Markdown and its links | A rebuildable search index and recall responses |

The operator client can submit a question, read evidence, and request or cancel a look. The recorder, planner, and memory workers have no direct drive interface. The custom types below belong to a proposed `mind_interfaces` package. Sensor messages and the ROS 2 action protocol use standard interfaces.

## Shared interfaces

| Name and type | Contract |
| --- | --- |
| `/vault/commit` · `mind_interfaces/srv/CommitRecord` | Request `string record_id`, `string folder`, `string markdown`, `string[] staged_assets`. Response `bool ok`, `string path`, `string error`. A successful response carries the vault-relative path, including extension. |
| `/vault/committed` · `mind_interfaces/msg/RecordCommitted` | `string record_id`, `string folder`, `string path`. The writer publishes after durability. Workers subscribe and filter by folder. Use reliable, volatile, keep-last depth 128 on both ends. A late subscriber discovers earlier records by scanning. |
| `/vault/recall` · `mind_interfaces/srv/Recall` | Request `string text`, `string[] folders`, `string anchor_id`, `bool include_superseded`, `uint32 limit`. Response `string[] paths`, `bool truncated`, `bool complete`, `string error`. The librarian serves operators and cognitive workers. |

Recall matches all case-folded query words in the ID, properties, heading, or body. Empty text admits all records in the selected folders. An empty folder list selects the whole vault. An optional anchor limits results to that ID, its direct sources, and records that cite it or supersede it through either supersession property. An unknown anchor returns an error. By default, offer current heads, including conflicting heads. For historical questions, include superseded notes and follow the exact versions cited at the time. A note prepared before a decision might have arrived later. Order by the number of matched words in the title, then by descending `recorded_at` and ascending ID. Return at most the requested limit, using 20 for zero and capping at 100. `truncated` means more results matched. `complete` is false if indexing is rebuilding or relevant notes could not be read, with the reason in `error`.

The librarian refreshes on commit and reconciles periodically. A caller needing read-after-write uses the exact `path` in the commit response. Indexes, work queues, and staging tokens live in private runtime storage outside the vault. The same audience restrictions apply to the index, drafts, attachments, and derived text as to their source material. A filesystem reader has access to the vault's contents, so admit material appropriate for that audience at acquisition.

## One durable commit

1. Hold the writer's exclusive vault lock. Accept the seven collection names and `.` for orientations. Derive the destination from the allowed folder, kind, and ID. Validate UTF-8, schema, required properties, and actual source and predecessor links. A producer with an uncommitted dependency retries after its source lands.
2. Check the destination first for an acknowledged or ambiguously completed request. If the complete Markdown bytes and installed asset digests match, return the same successful path, even when the original staging tokens have expired. Conflicting content at an existing ID returns `conflict`.
3. A local staging adapter accepts capture bytes and returns one opaque token per asset. Resolve tokens within writer-owned staging, in manifest order, and validate names, lengths, and SHA-256 digests against the capture note. Enforce the capture filename rule and reject path traversal or links out of the vault. Keep staging and final destinations on the same filesystem.
4. Install and flush verified assets, then publish the fully written note with an atomic rename and sync the containing directory or its platform equivalent. The appearance of the note is the commit point. Readers discover only ordinary record notes. A durable reservation journal lets the writer finish an interrupted install or reclaim unreferenced assets after recovery. Publish the hint after the commit point and acknowledge the client.

Use a short machine-readable prefix in `error`, followed by detail. `invalid` and `conflict` require review. `missing_source` and `unavailable` can be retried when the dependency or filesystem recovers. On storage exhaustion, the writer fails the commit and the executor withholds dispatch if it cannot persist a reservation. Readers continue to serve already committed records.

## Body, time, and restart

Drivers publish `sensor_msgs/msg/Image` on `/camera/image_raw` and `sensor_msgs/msg/JointState` on `/joint_states`. The recorder uses the sensor-data QoS profile. For a missing stream it preserves the observed gap where recording policy allows. Service clients and servers use the default reliable, volatile service profile. [ROS 2 QoS profiles](https://github.com/ros2/rmw/blob/rolling/rmw/include/rmw/qos_profiles.h)

A live caller can request `/agency/try_look` or `/agency/cancel_look`. Only the executor sends goals to `/body/look`. Its durable reservation consumes the authorization for that intention version. The head enforces bounds and expiry locally. A cancellation request can arrive before the body confirms a stop. The terminal result and subsequent observation are separate attempt events. The [attempt blueprint](attempts/.BLUEPRINT.md) gives the service fields, action goal, feedback, result, and restart behavior. [ROS 2 action semantics](https://design.ros2.org/articles/actions.html)

Keep sensor event time, UTC record creation, and elapsed local time distinct. Compare event times only in a common clock domain and epoch or with an explicit alignment. A backward jump starts a new epoch. Use a steady clock for duration limits at the body. Replay uses an isolated vault copy and ROS domain with live hardware disconnected. Startup and replay can reconstruct that a movement was requested. A missing return leaves its outcome unknown unless the body can supply the original result. [ROS 2 clock design](https://design.ros2.org/articles/clock_and_time.html)

| Shared parameter | Type and initial value | Use |
| --- | --- | --- |
| `vault_root` | string, required deployment path | Absolute vault location. Writer needs write access. Cognitive readers mount the same content read-only. |
| `reconcile_period_s` | integer, `30` | Default interval for rescanning committed notes. Individual workers can specify their own scan interval. |

Start the writer, recover incomplete installs, then start the librarian and workers. Subscribe before the initial scan and deduplicate by ID. Scan only `<kind>-<uuid>.md` at its declared depth, including `orientation-<uuid>.md` directly at the root. This leaves design files, workspace files, and attachment bytes outside the record index. A later rescan covers the interval between durable write and notification if the writer stopped there. Index state is disposable. The committed notes, their attachments, and the chain of decisions are the material needed to resume a question.
