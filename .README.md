# How I would keep a memory

I want to be able to change my mind about a sound and still hear what I heard. This vault gives the recording, the first interpretation, and the later explanation their own addresses. A later thought can cite all three.

Open [[Start here]] for the layout and a worked example. The root holds maps for questions that cut across folders, such as “What have I learned about my left wheel?” A map gives me a few good places to start reading. The underlying records live in the folder that describes how they were made.

A person, place, or part of my body can recur in every layer. A map for my workshop might bring together the sound of its door, the day I first crossed its threshold, and my current model of the ramp. When a wheel is replaced, I can still find the episodes that taught me how the old one handled that slope.

## Conventions shared by the folders

- Give each memory note a unique filename of the form `<kind>-<YYYYMMDDTHHMMSSZ>-<slug>.md`, for example `episode-20261126T080500Z-green-light.md`. Use the UTC creation time, choose a readable slug, and append `-2` if a name collides. A filename can stay stable as my vocabulary changes.
- Copy the folder’s `.TEMPLATE.md` to make a note. Fill `created` with the UTC time the note was written, such as `2026-11-26T08:05:00Z`. Put the time of the experience in the body or the designated event-time fields. A memory I write tomorrow can describe something I sensed today.
- In `sources`, list the notes that directly contributed to this one. Use quoted wikilinks, for example `sources: ["[[sample-20261126T080000Z-dock-light]]"]`. Firsthand records can start with `[]`. Keep comparisons, possible explanations, and next steps in the body so their relationship to the note is clear.
- Keep the original wording of a consequential interpretation. To correct it, write a dated successor, cite the earlier note and the evidence that changed it, and link forward from the earlier note. A search for the old explanation should lead to the correction.

Each folder’s `.README.md` explains what belongs there. Its `.SKILLS.md` describes how to turn inputs into useful records. Its `.TEMPLATE.md` gives the starting format. These dotfiles are available in the filesystem. The visible **Start here** note is the entry point inside Obsidian.
